# TellMeSensei v0.8.0 — Phase 1: Auto Watch Detector Prototype

## 0. Mission

We are starting development of **TellMeSensei v0.8.0**.

The major new feature is:

> **Auto Watch Mode** — the user selects a fixed question region once; TellMeSensei continuously watches that region and automatically detects when a new question has appeared and become visually stable.

For Phase 1, implement **ONLY the visual monitoring/detection prototype**.

Do **not** integrate OCR, DeepSeek, Vision, AnswerWindow automation, cancellation scheduling, or final Auto Watch UI yet.

The goal of Phase 1 is to answer one engineering question:

> Can a lightweight screen-based detector reliably distinguish:
>
> 1. the same question,
> 2. a page that is currently changing/loading/scrolling,
> 3. a new question that has become stable?

Define lightweight types.

Recommended:

```python
class MonitorState(Enum):
    STOPPED = ...
    SELECTING = ...
    ARMING = ...
    WATCHING = ...
    CHANGING = ...
    PAUSED = ...
    ERROR = ...
```

Phase 1 mainly exercises:

```text
STOPPED
ARMING
WATCHING
CHANGING
PAUSED
```

Also define dataclasses as useful, for example:

```python
@dataclass
class DetectorMetrics:
    change_ratio: float
    changed_bbox_ratio: float | None = None
```

and a lightweight `WatchRegion` model if needed.

Keep these models independent of DeepSeek/OCR.

---

# 6. Detector preprocessing

Implement a pure detector preprocessing function.

Input:

```python
QImage
```

or an equivalent deterministic image representation.

Output: a small normalized detector frame.

Required preprocessing:

```text
input ROI image
↓
preserve aspect ratio
↓
downscale so longest side ≈ 96 px
↓
grayscale
↓
normalized detector frame
```

Requirements:

- use smooth scaling
- no OCR
- no network
- no external ML
- do not add OpenCV unless there is a demonstrated need
- prefer Qt/Python/NumPy-compatible lightweight implementation
- do not add a heavyweight dependency just for this detector

If NumPy is already safely available in the Full runtime, it may be used.

---

# 7. Frame comparison

Implement deterministic frame comparison.

For each pixel:

```text
delta = abs(current - reference)
```

A pixel counts as changed only if:

```text
delta >= pixel_delta_threshold
```

Then calculate:

```text
change_ratio = changed_pixels / total_pixels
```

Also calculate the bounding rectangle of changed pixels when practical:

```text
changed_bbox_ratio = changed_bbox_area / detector_frame_area
```

Bounding-box ratio is **diagnostic/auxiliary in Phase 1**, not the primary decision criterion.

```text
DETECTOR_MAX_SIDE = 96

```

These are prototype defaults, not finalized product values.

# 9. Dual-reference model — mandatory

The coordinator must maintain **two independent references**.

## Baseline frame

```text
baseline_frame
```

Meaning:

> the most recently accepted stable question.

Used for:

```text
current vs baseline
```

to determine **novelty**.

## Previous sample

```text
previous_frame
```

Meaning:

> the detector frame observed one polling tick ago.

Used for:

```text
current vs previous
```

to determine **stability**.

Do not collapse these into one reference.

---

# 10. StabilityTracker

Create:

```text
app/auto_watch/stability.py
```

Responsibilities only:

- maintain consecutive stable sample count
- reset count on instability
- report when stable requirement has been reached

Conceptually:

```python
if change_ratio <= STABILITY_RATIO:
    stable_count += 1
else:
    stable_count = 0
```

Stable once:

```python
stable_count >= STABLE_SAMPLES_REQUIRED
```

Do not put generation, OCR, DeepSeek, workers, or UI into this class.

# 12. Initial ARMING logic

After an ROI/session starts:

```text
STOPPED
↓
ARMING
```

The current page may still be moving.

Therefore:

1. sample frames
2. compare current vs previous
3. wait until stable for N samples
4. establish `baseline_frame = current`
5. emit/log `INITIAL_STABLE_FRAME`
6. transition `ARMING → WATCHING`

Phase 1 does not analyze the frame.

---

# 13. WATCHING logic

During WATCHING, compare:

```text
current vs baseline
```

If:

```text
novelty_ratio < NOVELTY_RATIO
```

remain in WATCHING and update:

```text
previous_frame = current
```

If novelty becomes significant:

```text
current vs baseline >= NOVELTY_RATIO
```

transition:

```text
WATCHING → CHANGING
```

Reset the stability counter.

---

# 14. CHANGING logic

While CHANGING, every tick compares:

```text
current vs previous
```

If unstable:

```text
stable_count = 0
```

If stable:

```text
stable_count += 1
```

Only after:

```text
stable_count >= STABLE_SAMPLES_REQUIRED
```

perform another novelty check:

```text
current vs baseline
```

If still significantly different, accept:

```text
NEW_STABLE_FRAME
```

Then immediately:

```python
baseline_frame = current
previous_frame = current
```

and transition:

```text
CHANGING → WATCHING
```

Do not wait for an AI result; Phase 1 has no AI.

---

# 15. Temporary-change protection

Cover this case:

```text
baseline Q1
↓
large temporary popup/loading state
↓
popup disappears
↓
back to Q1
```

The coordinator may enter CHANGING.

After stability is reached, if current is again sufficiently similar to baseline, this is **not** a new question.

Return to WATCHING without emitting `NEW_STABLE_FRAME`.

This behavior must have a unit test.

---

# 16. Pause / Resume prototype

Phase 1 may implement basic coordinator-level:

```python
pause()
resume()
stop()
```

## Pause

```text
state → PAUSED
```

Ignore detector ticks while paused.

## Resume

Do not immediately assume the old state is valid.

Enter ARMING / re-arm mode.

After re-arming:

- if current is sufficiently similar to baseline, return WATCHING without a new-frame event
- if current has genuinely changed and stabilizes, emit a new stable-frame event

No AI integration yet.

---

# 17. Minimal real-screen sampler

We need a small real-screen prototype.

Do not create final Watch UI yet.

Use the smallest safe sampling mechanism that repeatedly captures a previously selected fixed ROI.

Preferred direction:

```text
QTimer
interval = 250 ms
```

Each tick:

1. capture watched ROI
2. produce detector frame
3. pass it to coordinator

Do not run OCR/API.

# 23. Unit tests — detector

Add:

```text
tests/test_auto_watch_detector.py
```

Use synthetic deterministic images.

Required cases:

### Same frame

```text
A vs A
```

Expected: `change_ratio ≈ 0`.

### Tiny local change

Small rectangle changes.

Expected: small change ratio.

### Large content change

Large region changes.

Expected: change ratio above novelty threshold.

### Pixel noise below threshold

Small grayscale delta below `PIXEL_DELTA_THRESHOLD`.

Expected: not counted as changed.

### Bounding-box metric

Known changed rectangle gives expected approximate bbox coverage.

# 24. Unit tests — stability

Add:

```text
tests/test_auto_watch_stability.py
```

Required:

- unstable sample resets count
- first stable sample → 1
- second → 2
- third → stable
- instability after count 2 resets to 0

---

# 25. Unit tests — coordinator

Add:

```text
tests/test_auto_watch_coordinator.py
```

Required scenarios:

### Initial stable page

```text
ARMING
→ stable N samples
→ INITIAL_STABLE_FRAME
→ WATCHING
```

Exactly once.

### Same question stays static

No repeated `NEW_STABLE_FRAME`.

### Normal Q1 → Q2

```text
WATCHING
→ novelty
→ CHANGING
→ stable
→ NEW_STABLE_FRAME
→ WATCHING
```

Exactly once.

### Loading sequence

```text
Q1
white
partial
partial2
Q2
Q2
Q2
```

Only final Q2 accepted.

### Scroll-like continuous changes

Continuous instability must not emit a new stable frame early.

### Temporary popup then return to baseline

Must not emit a new question.

### Pause

Ticks ignored.

### Resume unchanged

Must not duplicate a new-question event.

### Resume after page changed

Eventually emits a new stable frame.

---

# 26. No timing-dependent flaky tests

Coordinator tests must not depend on real wall-clock sleeps.

Inject frames synchronously.

Use stable sample counts rather than waiting real 750 ms in unit tests.

QTimer should only be tested in a small integration/smoke layer.

---

# 27. Real manual validation

After unit tests pass, run the detector prototype against real content.

Test at least:

### Scenario A — static question

Leave unchanged for 30 seconds.

Expected: no repeated `NEW_STABLE_FRAME`.

### Scenario B — mouse / hover

Move mouse through ROI and hover buttons.

Expected: ideally no new-question event.

Record metrics.

### Scenario C — scrolling

Scroll continuously.

Expected: CHANGING while moving.

Only after stopping should stable acceptance occur.

### Scenario D — normal next question

Expected: exactly one `NEW_STABLE_FRAME`.

### Scenario E — loading/reflow

Use a page that visibly changes during load if possible.

Expected: do not accept a half-loaded intermediate frame.

### Scenario F — rapid next-next-next

Expected: detector reports only stable states; intermediate frames that never remain stable should not be accepted.
