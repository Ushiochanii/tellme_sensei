# TellMeSensei v0.8.0 — Auto Watch Mode 最终实施方案

> 文档状态：Implementation Plan / Final Draft  
> 基线版本：TellMeSensei v0.7.1  
> 开发基线：`main` @ `2e1dc6940c4406b2eb3fe3293915662920912402`  
> 目标版本：v0.8.0  
> 核心功能：固定题目区域自动监控、自动换题检测、自动触发 Text/OCR 或 Vision 分析

---

# 1. 产品目标

v0.8.0 增加 **Auto Watch Mode**：用户只需要框选一次题目区域，TellMeSensei 持续监控该固定区域；当检测到题目内容发生显著变化且页面稳定后，自动触发现有分析流程。

典型流程：

```text
Start Auto Watch
    ↓
Choose Text/OCR or Vision
    ↓
Select fixed question region (ROI)
    ↓
Wait until current page is stable
    ↓
Analyze current question once
    ↓
Watch region continuously
    ↓
Question changes
    ↓
Wait until new page is stable
    ↓
Analyze newest stable question
    ↓
Repeat
```

核心定义：

> Auto Watch 不是“循环截图”，而是“检测新的稳定题目，并自动触发已有分析 pipeline”。

# 3. 最终技术路线

正式采用：

> **Screen-based ROI Monitoring + Dual-reference Visual Detection + Stable Debounce + Latest-Wins Dispatcher + Cancellation + Generation Guard**

整体结构：

```text
Watched ROI
    ↓
Lightweight Detector Capture
    ↓
Dual-reference Visual Detector
    ├── Current vs Baseline → Novelty
    └── Current vs Previous → Stability
    ↓
Stable New Frame Confirmed
    ↓
Generation Manager
    ↓
Latest-Wins Analysis Dispatcher
    ↓
Existing Text/OCR or Vision Pipeline
    ↓
Generation Guard
    ↓
AnswerWindow
```

原则：Auto Watch **不得复制或重新实现** OCR、Vision、DeepSeek、AnswerWindow 业务逻辑。

# 4. 核心检测算法

## 4.1 Detector Frame

每次监控采样不使用原始 ROI 全分辨率图像进行比较。

流程：

```text
Full ROI Screenshot
    ↓
Aspect-ratio-preserving resize
    ↓
Longest side ≈ 96 px
    ↓
Grayscale
    ↓
Small detector frame
```

建议：

- 最大边：96 px
- 保持宽高比
- 灰度：8-bit
- 使用平滑缩放
- 不把 detector frame 用于 OCR / Vision

目的：

- 降低 CPU
- 降低鼠标、抗锯齿、细小 UI 动画影响
- 保留题目主体变化

---

# 5. Dual-reference Detection

每个 Watch Session 同时维护两个 reference。

## 5.1 Baseline Frame

表示：

> 最近一次已经确认并接受的稳定题目。

用于判断 **Novelty（是否已经换题）**。

```text
novelty = compare(current, baseline)
```

## 5.2 Previous Sample

表示：

> 上一次 detector tick 看到的画面。

用于判断 **Stability（网页现在是否还在变化）**。

```text
stability = compare(current, previous_sample)
```

这个设计避免把“跟上一题不一样”和“当前还在加载”混为一谈。

---

# 6. Frame Difference 指标

第一版 detector 使用透明、可调试的灰度像素差。

对于 detector frame 中每个像素：

```text
pixel_delta = abs(current_pixel - reference_pixel)
```

只有当：

```text
pixel_delta >= PIXEL_DELTA_THRESHOLD
```

才计为 changed pixel。

然后计算：

```text
change_ratio = changed_pixels / total_pixels
```

建议初始参数（仅 prototype 初始值，不视为最终产品常量）：

```text
PIXEL_DELTA_THRESHOLD = 12~18 / 255
NOVELTY_RATIO = 0.05~0.08
STABILITY_RATIO = 0.01~0.02
```

最终 threshold 必须由真实网页测试数据确定。

---

# 7. Change Bounding Box（辅助指标）

Phase 1 可以同时输出 changed-pixel bounding box coverage：

```text
changed_bbox_area / frame_area
```

用途：调试与 telemetry/logging。

v0.8.0 初版不建议让它成为绝对硬门槛，但可以作为后续误报治理的辅助信号。

例如：

- timer：change_ratio 小、bbox 小
- 整题切换：change_ratio 大、bbox 通常也大

---

# 8. 默认采样与稳定参数

初始建议：

| 参数 | 默认值 |
|---|---:|
| Poll interval | 250 ms |
| Detector image longest side | 96 px |
| Stable samples required | 3 |
| Stable window | 约 500–750 ms |
| Novelty ratio | 约 5–8% |
| Stability ratio | 约 1–2% |

第一版不要暴露这些工程参数给普通用户。

如果真实测试后需要用户调节，未来只提供：

```text
Sensitivity: Low / Normal / High
```

而不是直接暴露数学阈值。

# 9. 新题判定流程

正常 WATCHING 状态：

```text
sample current
    ↓
compare current vs baseline
    ↓
novelty below threshold
    ↓
remain WATCHING
```

检测到 significant novelty：

```text
current differs from baseline
    ↓
enter CHANGING
```

CHANGING 状态：

```text
sample current
    ↓
compare current vs previous_sample
    ↓
if still changing:
    stable_count = 0

if sufficiently stable:
    stable_count += 1

if stable_count >= required_samples
AND current still differs significantly from baseline:
    accept new stable frame
```

确认新题后立即：

```text
generation += 1
baseline = current_detector_frame
capture full-resolution ROI
submit newest analysis request
```

注意：**baseline 在分析启动前立即更新，不等待 AI 结果。**

# 10. 首次选区行为

用户框选 ROI 后进入 ARMING：

```text
Select ROI
    ↓
ARMING
    ↓
等待连续稳定帧
    ↓
建立 baseline
    ↓
generation = 1
    ↓
自动分析当前题
    ↓
WATCHING
```

不要求用户再点一次 Analyze。

# 11. Monitor 与 Analysis 分离

不得使用一个单状态机把所有行为串成：

```text
WATCHING → PROCESSING → WATCHING
```

因为 AI processing 时必须继续检测新题。

采用两个独立状态域。

## 11.1 MonitorState

```text
STOPPED
SELECTING
ARMING
WATCHING
CHANGING
PAUSED
ERROR
```

## 11.2 AnalysisState

```text
IDLE
RUNNING
CANCELLING
```

允许合法组合：

```text
MonitorState = CHANGING
AnalysisState = RUNNING
```

含义：上一题仍在分析，但屏幕已经开始进入下一题。

---

# 12. Latest Wins 调度模型

Auto Watch 不维护历史题 queue。

只允许：

```text
1 Active Job
+
0 or 1 Latest Pending Job
```

当新题出现：

```text
active = Q1
new stable = Q2

pending = Q2
request cancel Q1
```

如果 Q1 cancellation 尚未完成时又出现：

```text
Q3
Q4
```

则不断覆盖：

```text
pending = Q4
```

而不是：

```text
pending = [Q2, Q3, Q4]
```

旧 Worker 真正 finished 后，只启动最新 pending。

---

# 13. Generation Guard

每个 accepted stable question 获得唯一递增 generation：

```text
Q1 → generation 1
Q2 → generation 2
Q3 → generation 3
```

所有 Auto Watch analysis request 必须携带 generation。

所有 result/error/cancel callback 在进入 UI 前必须验证：

```python
if result_generation != current_generation:
    discard_as_stale()
```

Generation Guard 是正确性保障，不是性能优化。

它必须覆盖：

- Text OCR result
- DeepSeek text result
- Vision result
- error callback
- retry-related completion if tied to stale Auto Watch job

旧 generation 绝不能覆盖当前题状态。

---

# 14. Cancellation 策略

新 stable question 到达时：

1. 立即增加 generation
2. 立即更新 baseline
3. 将 newest request 写入 pending
4. 如果有 active analysis：调用已有 cancellation 机制
5. 等 active Worker 完整 finished/cleanup
6. 启动 latest pending

不得：

- 同时运行无限多个分析 worker
- 仅依赖 cancellation 而不做 generation check
- 因 cancellation 失败而停止 Watch

---

# 15. Pause / Resume

## Pause

Pause 只暂停自动监控和自动触发。

默认行为：

- 停止 detector timer
- 保留 ROI
- 保留 baseline
- 当前已经运行的分析任务不自动 cancel
- Watch UI 状态变为 Paused

## Resume

Resume 不直接回 WATCHING，而进入 ARMING/REARM：

```text
Resume
    ↓
重新观察当前 ROI 是否稳定
    ↓
if current ≈ baseline:
    WATCHING，不重复分析

if current differs from baseline:
    等稳定
    generation++
    自动分析当前题
```

---

# 16. Analyze Now

Analyze Now 是必须提供的人工 fallback。

行为：

```text
capture current ROI
    ↓
建立当前 detector frame
    ↓
generation += 1
    ↓
baseline = current frame
    ↓
latest pending = current full-res capture
    ↓
cancel stale active job if needed
    ↓
run newest analysis
```

即使 detector 没判断为新题，也强制当前题成为新的 generation。

---

# 17. Stop

Stop Auto Watch：

- 停止 detector timer
- 清除 ROI session
- 关闭 Watch overlay / mini controller
- 清空 pending request
- 对 active Auto Watch analysis 发出 cancellation
- 完成 worker cleanup 后回 STOPPED
- 不影响普通手动 Text/OCR、Vision 模式后续使用

---

WatchRegion 必须保存：

# 23. Screen / ROI 失效处理

如果：

- 显示器断开
- resolution 改变
- screen geometry 变化导致 ROI 不再有效
- capture API 返回无效区域

Auto Watch：

```text
PAUSED / ERROR
Region is no longer available. Select a new region.
```

不要进入高频错误循环。

---

# 24. Capture Permission Error

macOS Screen Recording 权限不可用时：

- Auto Watch 不启动 polling loop
- 显示一次明确错误
- 停留 STOPPED/ERROR
- 不每 250 ms 重复弹窗

复用当前 capture permission handling，不建立第二套权限逻辑。

---

# 25. API / OCR Error

某一道题分析失败：

- AnswerWindow 显示该 generation 的错误（前提：generation 仍 current）
- Auto Watch 继续运行
- 下一道 stable question 仍可自动分析

分析失败不得自动停止 Watch Session。

# 27. 模块职责

## 27.1 `models.py`

定义：

- `MonitorState`
- `AnalysisState`
- `WatchRegion`
- `DetectorMetrics`
- `WatchFrame`
- `PendingAnalysis`
- `AutoWatchMode`（TEXT / VISION，或复用 `AnalysisMode`）

使用 dataclass / Enum，尽量保持纯逻辑、可测试。

## 27.2 `detector.py`

职责：

- QImage / raw image → grayscale small detector frame
- compare frames
- 输出 change_ratio
- 可选 changed bbox coverage

要求：

- 无网络
- 无 OCR
- 无 UI
- deterministic
- 可用 synthetic arrays/images 单测

## 27.3 `stability.py`

职责：

- 维护 stable_count
- 根据 `current vs previous` metrics 判断连续稳定帧
- reset
- 不管理 generation / worker

## 27.4 `coordinator.py`

核心纯逻辑协调器。

维护：

- monitor state
- baseline detector frame
- previous detector frame
- generation
- ROI
- stability tracker

输入事件：

- region_selected
- detector_tick(frame)
- pause
- resume
- analyze_now
- stop
- capture_error

输出 signals/events：

- stable_question_accepted(generation, ...)
- status_changed
- analysis_requested
- watch_stopped

尽量让状态机可在没有真实 GUI 的情况下单测。

## 27.5 `dispatcher.py`

负责：

- active generation
- latest pending request
- cancellation request
- active worker finished 后启动 latest pending
- stale result filtering辅助

不要把 OCR/DeepSeek 实现在这里。

## 27.6 `watch_overlay.py`

只负责：

- ROI border
- mini controls
- state presentation
- click-through / focus behavior

不做 detector 数学。

当前 Full UI 仍以 `MainWindow` 负责 Text/Vision capture 和 worker orchestration。

```text

```

或等价抽象，把：

- 手动截图完成
- Auto Watch full ROI capture

汇入同一现有分析路径。

如果当前结构不允许安全复用，可以做最小提取，但禁止“为了 Auto Watch 顺手重写整个 pipeline”。

# 29. 线程模型

Detector 第一版使用 GUI thread 的 `QTimer`：

```text
QTimer interval = 250 ms
```

每 tick：

- 截取 ROI
- 缩图
- 灰度
- 做小图 diff

前提：真实 profiling 证明单 tick 足够轻，不造成 UI 卡顿。

如果 screen capture 本身在某平台明显阻塞，再把 sampling 移至独立 worker；不要预先引入复杂永久线程。

OCR / Vision / DeepSeek 继续使用现有 worker/thread/cancellation architecture。

# 30. 性能预算

目标：Auto Watch idle 时用户几乎感觉不到额外负载。

初步性能预算：

- 4 detector ticks / sec
- detector frame ≈ 96 px longest side
- diff 操作毫秒级以内
- 不持续 OCR
- 不持续 API 请求
- 只有稳定新题触发 full-resolution analysis capture

Phase 1 必须记录简单 timing log：


用于判断 GUI thread 是否可接受。

# 37. 核心自动化测试矩阵

## Detector

- identical frames → zero/near-zero novelty
- localized tiny change → below novelty threshold
- large text-region change → above novelty threshold
- noisy anti-aliasing-like delta → appropriately filtered
- changed bbox metrics deterministic

## Stability

- continuous changing frames → never stable
- N consecutive stable frames → stable exactly once
- one unstable frame resets stable_count

## Coordinator

- initial selection → ARMING
- initial stable → generation 1 accepted
- same baseline → no repeat
- novelty → CHANGING
- stable new frame → generation increment
- Pause → no acceptance
- Resume same frame → no duplicate analysis
- Resume changed frame → new generation
- Analyze Now → forced new generation
- Stop → clean state

## Dispatcher

- one active job only
- new request becomes latest pending
- Q2 pending replaced by Q3
- active finished starts latest pending
- stale result ignored
- stale error ignored
- cancellation failure does not violate generation guard

# 40. v0.8.0 的关键技术决策（冻结）

以下作为当前实施方案的默认冻结决策：

- 检测路线：screen-based，不做 browser-specific integration
- Detector：downscaled grayscale pixel diff
- Detector 图像：最长边约 96 px
- Poll：250 ms 起步
- Novelty：current vs baseline
- Stability：current vs previous sample
- Stable requirement：3 consecutive samples 起步
- Queue：不排历史，只保留 latest pending
- 新题：尝试 cancel old active job
- Safety：必须 generation guard
- 首次选区：稳定后立即分析
- 新题分析期间：保留旧答案直到新结果到达
- Pause：暂停 monitor，不自动取消当前请求
- Resume：重新 ARM
- Analyze Now：强制新 generation
- ROI：v0.8.0 session-only，不跨重启保存
- ROI：单 screen 内
- Error：单题分析错误不停止 Watch
- AnswerWindow：尽可能放在 ROI 外部
- Advanced detector：真实数据证明必要后再加入 SSIM/pHash
