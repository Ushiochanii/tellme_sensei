# v0.9.0 Settings UX Hardening

Status: Accepted for implementation

## Background and problem

The v0.9.0 provider refactor made Text AI, Vision AI, provider credentials, and
OCR runtime selection independently configurable. The first functional UI puts
those controls on the correct pages, but the relationship between a selected
AI provider and its shared credential is indirect, custom-model editing is not
explicit, connection-test feedback is visually weak, and active OCR mode is not
prominent enough.

## Goals

- Make each Text/Vision capability read as one complete configuration.
- Make shared provider credentials discoverable without duplicating secrets.
- Expose custom model entry only after an explicit Custom choice.
- Give connection tests local busy/success/error feedback and cancellation.
- Put shared request timeout in an Advanced section with numeric validation.
- Preserve inactive OCR selections while clearly emphasizing the active mode.
- Preserve configuration, environment override, shortcut, and runtime behavior.

## Non-goals

- No provider, transport, persistence, or OCR lifecycle redesign.
- No changes to provider/model catalog contents.
- No application-wide theme migration or custom window chrome.

## Proposed interaction

Text AI and Vision AI remain separate cards. Each card contains Provider,
Model, a credential-status row, a Manage Credentials action, and its own Test /
Cancel / status region. Manage Credentials selects the relevant provider in one
shared credential editor; keys remain stored once per provider.

Known models use a non-editable combo. Selecting Custom reveals a dedicated
model-ID field. Request timeout moves into an Advanced card and uses a bounded
numeric control. Local and Online OCR summaries expose a selected state and
their existing Manage actions remain available.

Connection operations disable only controls that could invalidate the active
request, keep cancellation available, and expose status using text plus a
semantic state property.

## Test plan

- Text/Vision provider changes update credential status and Manage routing.
- Known/custom model selection round-trips without losing custom IDs.
- Timeout is numeric and persists to both capability configs.
- Busy/success/error states remain local and cancellable.
- OCR active mode is visible while inactive selections remain retained.
- Existing Settings, provider, OCR, language, and shortcut regression tests pass.
- Compile, Core smoke, and whitespace checks pass.

## Definition of Done

The Settings UI communicates provider ownership without requiring the user to
infer relationships, custom values have explicit controls, operation states are
clear and keyboard reachable, persistence remains compatible, and focused UI
tests cover the new state transitions.
